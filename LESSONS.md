## Сессия 1 (2026-07-29)

**Что сработало / что держать в уме**

- ✅ Жёсткое правило среды: работать только в ветке `arena/019faf3c-supergame`,
  пушить только её; в `main` код попадает через PR. Это расходится с
  «работай напрямую в main» из README — правило среды важнее, расхождение
  писать в SESSION_LOG, чтобы не удивлять себя в будущих сессиях.
- ⚠️ **Токен агента не умеет пушить workflow-файлы** (нужен permission
  `workflows`). Не тратить время на повторные попытки: изменения в
  `.github/workflows/` передавать человеку через CHECKLIST (вставка через
  веб-интерфейс) или просить выдать приложению право. GitHub даёт похожую
  ошибку и через REST API contents — проверено, обхода нет.
- ✅ `npm ci` в CI требует `package-lock.json` в репозитории — генерировать
  `npm install` локально и коммитить lock при каждой смене package.json.
- ✅ Сайт без сборки: Vercel по умолчанию отдаёт статику из корня —
  `vercel.json` не создавать без реальной нужды (меньше конфигов — меньше грабель).
- ✅ Репозиторий приватный и маленький: документы памяти живут в корне рядом
  с кодом — так их точно не потеряешь между сессиями.
- ⚠️ Эмодзи как «спрайты»: до первого визуала у человека проверять базовый
  набор иконок через `CHECKLIST.md` — разные ОС рисуют их по-разному.
- ⚠️ Не плодить игровую логику до сессии 4: README это запрещает, а ранняя
  логика до финализации GDD — выброшенная работа.
