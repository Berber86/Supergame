# Уроки проекта

Накопленный опыт и находки. Правило: критика без конкретной, реализуемой альтернативы не засчитывается.

## Критика

### Сессия 2 (Critic) — находки и принятые альтернативы

1. **Находка:** рекомендованный CD вариант B («Драконьи рейды») не содержал «захвата королевств» — а это часть одобренного человеком описания жанра. Концепция, игнорирующая одобренную рамку, не может быть финализирована.
   **Альтернатива:** слить B с C: королевства становятся целями рейдов и мета-слоем. → *принято (GDD §2–3).*
2. **Находка:** «глубокие синергии» в idle-жанре вырождаются в список множителей без решений (риск, который CD сам отметил для варианта A).
   **Альтернатива:** синергии существуют только в активной петле, где есть выбор (рейд, выбор реликвий); idle-петля остаётся простой; комбо имеют имена и открываются экспериментом. → *принято (GDD §3.3, правило 6).*
3. **Находка:** две петли (idle + рейд) = риск двух недоделанных половинок и раздутого скоупа.
   **Альтернатива:** scope-контракт MLP (3 королевства, 12–15 реликвий, 3 семейства) + поэтапная реализация: S4 — только пещера, S5 — только рейд v1. → *принято (GDD §4, ROADMAP).*
4. **Находка:** потолок «≤ 1000» без контракта пейсинга делает прогрессию либо тривиальной (потолок за минуту), либо бессмысленной (долгая скучная дорога к цифрам, которые «не растут»).
   **Альтернатива:** контракт пейсинга: потолок ~15–20 минут; ценность после потолка — контентные цели (королевства, реликвии, достижения); перерождение возвращает к малым числам с процентными множителями. → *принято (GDD §3.4).*
5. **Находка:** офлайн-доход в статик-сайте без бэкенда нельзя «крутить» в фоне — непонятно, как считать накопления.
   **Альтернатива:** расчёт при загрузке по timestamp в localStorage, кап 8 часов (анти-читерство + защита потолка ≤1000), юнит-тест на «подделку времени». → *принято (GDD §3.5, требование для S4).*
6. **Находка (процесс):** пул карточек хаоса — 36 шт. (минимум 30 выполнен), но при бесконечной жизни проекта он иссякнет.
   **Альтернатива:** CD в свою следующую сессию пополняет пул до ~50 карт (новые карты добавляются в конец, последовательность использования не нарушается). → *принято, требование к следующей сессии CD.*

## Находки Творческого директора (сессия 1)

- **Синергии работают, когда их открываешь сам.** Игроку приятнее случайно обнаружить комбинацию, чем прочитать её в подсказке. Проектировать синергии надо «на обнаружение», а не «на прочтение».
- **Инфляция чисел убивает ощущение прогресса.** Ограничение «всё ≤ 1000» (карточка №1) заставляет делать сбросы-престижи осмысленными. Это осознанное отличие от типовых кликеров.
- **Idle-жанр рискует стать пассивным.** Чтобы удержать «глубокие синергии», нужна активная петля решений (выбор реликвий/целей), а не только накопление множителей.

## Процессные заметки

- Сессия 1: уточняющие вопросы человеку (3 шт., по 4 варианта) — ответы получены сразу, ASSUMPTION-пометок не потребовалось.
- Readme.md редактировать нельзя даже для заполнения «пустого» раздела жанра — ответы человека фиксируются в GDD.md и SESSION_LOG.md.
- Сессия 2: конфликтов с одобренными человеком решениями не обнаружено → вопросы человеку не задавались, Критик решил сам (по правилам эскалации).

## Заметки Кодера (сессия 3)

- **Чистые функции = тестируемость.** Экономика, пейсинг и сейв спроектированы как чистые функции `(state, ...) → value`; рендер отделён через шину событий. Это окупится на десятках сессий.
- **Кап офлайн-дохода — анти-читерство и защита контракта «≤ 1000» одновременно.** Подделка времени тестируется напрямую через `computeOfflineMs(lastSavedAt, now)`.
- **Контент отдельно от логики** (`content/*.ts`): добавление реликвии — правка данных, а не кода; риск регрессий минимален.
- **Ключ сейва версионируется.** Несовместимое изменение формата = новый ключ (старый прогресс теряется осознанно), повреждённый JSON = новый старт без краша.

## Процессные находки (сессия 13, Coder)

- **«Логика есть — фичи нет».** Сессия 5 отчиталась о выполненной рейд-петле, но `raid.ts`
  ни разу не импортировался в `main.ts`: тесты зелёные, а игрок в рейд попасть не мог.
  **Правило на будущее:** критерий приёмки считается выполненным, только если фича доступна
  из UI. Дешёвая проверка — `grep` импортов нового модуля в точке входа перед коммитом.
- **Эффекты контента — числами, а не текстом.** Урон реликвий парсился из строк описаний
  (`effect.includes('+3 урон')`): любая правка формулировки молча ломала баланс.
  Числовые поля (`damage`, `lootPct`) + балансные тесты закрывают этот класс ошибок.
- **Случайность в интеграционных тестах.** Тест полного цикла зависит от случайных предложений
  реликвий. Вместо мока — допущены повторные попытки рейда (как у живого игрока) и прогон
  теста 5 раз подряд для проверки на флак.
