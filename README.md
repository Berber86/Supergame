# The Long Line

Веб-игра на **TypeScript + Vite + Phaser 3**: игрок ведёт индивидуально эволюционирующий ростер от Каменного века до далёкого будущего, расставляет 4–8 бойцов на гексах и наблюдает автоматический бой.

Игра полностью готова к публикации на **Vercel** (сборка настроена, прогресс автоматически сохраняется в LocalStorage) и имеет заложенную архитектуру для будущего онлайн-PvP.

---

## 🚀 Быстрый старт

```bash
npm install
npm run dev          # запустить локальный сервер разработки (http://localhost:5173)
npm run build        # запустить проверку типов и собрать продакшен-бандл
npm run preview      # локально протестировать продакшен-сборку
npm test             # запустить все автоматические тесты (включая симуляцию баланса)
```

Требуется Node.js 18+.

### 3. Балансировка v2 и симуляция сложности
- Разработан и внедрён **автоматический скрипт тестирования баланса** (`scripts/balance-test.ts`), имитирующий действия среднего игрока на протяжении 40 волн (найм, лечение, своевременная эволюция, оптимальная расстановка с учётом рельефа).
- На основе результатов симуляции (изначально игра была слишком простой) проведён тюнинг коэффициентов сложности:
  - `BASE_STAT_MULT` настроен на **0.90**
  - `ELITE_STAT_MULT` настроен на **1.18**
  - `PRESSURE_PER_WAVE` настроен на **0.003**
- Это обеспечило идеальную кривую сложности: средняя глубина прохождения составляет **33.8 волн**, предлагая игроку нарастающий вызов ближе к финалу.

### 4. Готовность к PvP (Архитектура будущего)
- Вся логика боя вынесена в чистую, независимую от Phaser функцию в модуле `src/systems/PvPSimulator.ts`.
- Модуль принимает сериализуемые структуры данных состава (`PvPUnitEntry`), запускает симуляцию в headless-режиме (на сервере или клиенте) и возвращает детерминированный результат.
- Написано подробное руководство (внутри `src/systems/PvPSimulator.ts` и ниже в README) по интеграции клиент-серверного обмена, синхронизации ГСЧ по SEED и детерминированному реплею событий на клиентах.

## 🎮 Игровой цикл

1. **Хаб** — управление ростером (до 12 юнитов), лечение раненых, найм новобранцев Эпохи I, выбор эволюции для опытных бойцов.
2. **Состав** — выбор от 4 до 8 дееспособных воинов для участия в волне.
3. **Расстановка** — перетаскивание юнитов мышкой (drag-and-drop) на левые 3 колонки гексов или клик по кнопке «Авто» (ИИ распределит стрелков на холмы, поддержку в леса, а танков на передовую).
4. **Автоматический бой** — воспроизведение детерминированной симуляции на гексагональной сетке с частотой 10 Гц.
5. **Последствия** — начисление золота и опыта, перенос урона в мета-слой. Поражение не штрафует игрока потерей HP, позволяя перерасставить воинов и попробовать ещё раз.

## 🖧 Архитектура PvP (Руководство по интеграции)

Благодаря детерминированности боевой симуляции `CombatSystem` на базе единого SEED генератора случайных чисел (`RNG`), подключение реального PvP реализуется без необходимости синхронизации координат каждого кадра:

1. **Обмен составами (JSON)**:
   При клике "В бой" клиент сериализует выбранный отряд в JSON и отправляет его на бэкенд:
   ```json
   [
     { "id": "ru1", "template": { "id": "iron_legionary", "hp": 230, "atk": 22, ... }, "col": 1, "row": 3, "currentHp": 230 },
     { "id": "ru3", "template": { "id": "longbowman", "hp": 110, "atk": 29, ... }, "col": 0, "row": 2, "currentHp": 110 }
   ]
   ```
2. **Серверный арбитраж**:
   - Бэкенд (Node.js) принимает составы двух игроков (Игрок А — 'player', Игрок Б — 'enemy').
   - Генерирует общий `SEED` матча.
   - Запускает чистую симуляцию `simulatePvPCombat(squadA, squadB, seed)` из `src/systems/PvPSimulator.ts`.
   - Записывает итоговый результат и отправляет игрокам `SEED` матча и составы друг друга.
3. **Воспроизведение (Реплей)**:
   - Клиенты получают те же составы и тот же `SEED`.
   - Локально инициализируют `CombatSystem` и запускают бой.
   - Поскольку ГСЧ и алгоритмы движения абсолютно детерминированы, оба игрока видят абсолютно идентичный бой кадр в кадр локально, без сетевых задержек.

## 🌐 Деплой на Vercel

Проект полностью оптимизирован под хостинг на **Vercel**:

### Пошаговая инструкция для публикации:
1. Зарегистрируйтесь на [Vercel](https://vercel.com).
2. Подключите свой аккаунт к GitHub.
3. Нажмите кнопку **"Add New" -> "Project"** в панели Vercel.
4. Выберите репозиторий `Supergame` (или вашу ветку).
5. Настройки проекта определятся автоматически (проект на Vite):
   - **Framework Preset**: `Vite`
   - **Build Command**: `npm run build` (выполняет `tsc --noEmit && vite build`)
   - **Output Directory**: `dist`
6. Нажмите **Deploy**. Через 30 секунд игра будет доступна по публичной ссылке!

**Работа сохранений в проде**: Механизм сохранений использует стандартный API браузера `window.localStorage`. Он полностью работоспособен на любом домене Vercel и сохраняет прогресс прохождения игрока даже после перезагрузки вкладки.

## 🧪 Набор автоматических тестов

В проекте настроена строгая система автоматической верификации всех механик:

- `npm run test:sim` — проверяет детерминированность боя, корректность нанесения урона, смертей и лечения.
- `npm run test:campaign` — тестирует экономический слой (сохранение/загрузку, найм, формулы стоимости).
- `npm run test:integration` — интеграция боя и кампании (перенос HP, начисление XP, миграция сейвов).
- `npm run test:stage4` — 44 жесткие проверки контента всех 8 эпох, баланса моно-линий и срабатывания всех способностей в FSM.
- `npm run test:balance` — запуск симуляции баланса кривой сложности на 5 кампаниях по 40 волн.
- `npm test` — комплексный прогон всех тестов вместе с полной проверкой типов TypeScript.
