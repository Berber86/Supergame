# The Long Line — боевой прототип

Прототип для веб-игры **The Long Line** на **TypeScript + Vite + Phaser 3**.

- **Этап 1** — боевая система на гекс-сетке: ручная расстановка → авто-симуляция боя → результат.
- **Этап 2** — мета-цикл кампании: **Хаб → Выбор состава → Расстановка → Бой → Хаб**,
  экономика, персистентный ростер, сохранение в LocalStorage.

> **Ключевое архитектурное требование выполнено:** боевая логика (`systems/`) и
> мета-логика (`meta/`) полностью отделены от рендеринга (Phaser-сцены) и не
> импортируют Phaser. Все слои покрыты headless-тестами (`scripts/`).

---

## Быстрый старт

```bash
npm install
npm run dev        # дев-сервер: http://localhost:5173
# или
npm run build      # typecheck + production-сборка в dist/
npm run preview    # предпросмотр сборки
```

Требуется Node 18+.

## Как играть (полный цикл)

1. **Хаб.** Видите ростер (до 12 слотов), валюту и номер волны. Раненые юниты
   помечены «РАНЕН», сражённые (0 HP) — «СРАЖЁН». Кнопки:
   - **«Нанять юнита»** — модалка с 9 шаблонами эпохи 1 (тратит валюту).
   - **«Лечить»** на карточке / **«Лечить всех»** — восстановление HP за валюту.
   - **«В бой»** — перейти к выбору состава (нужно ≥4 боеспособных юнитов).
2. **Выбор состава.** Отметьте 4–8 юнитов, которые пойдут в волну (сражённых
   выбрать нельзя). «Дальше: расстановка →».
3. **Расстановка.** Перетащите выбранных юнитов на синюю зону (левые 3 колонки).
   Красная зона — враги этой волны. «Начать бой». (Есть «Авто»-расстановка.)
4. **Бой** идёт автоматически (~10 тиков/сек).
5. **Результат.**
   - **Победа** → доход начислен, HP выживших/павших переносится в ростер, волна +1 → Хаб.
   - **Поражение** → без потери валюты и юнитов: «Заново» (к выбору состава) или «В хаб».

Прогресс (ростер со статами/опытом/HP, валюта, волна) сохраняется в LocalStorage
и восстанавливается после перезагрузки страницы. Кнопка «Новый старт» сбрасывает кампанию.

### Разделение логики и рендера

- `CombatSystem` — **единственный источник истины** о состоянии боя. Работает в
  фиксированном шаге 10 Гц и не знает о Phaser.
- Связь с рендером — через **очередь событий** `sim.events`: `move`, `attack`,
  `death`, `heal`, `state`. `BattleScene` за кадр «вычитывает» их и проигрывает
  как анимации (твины перемещения, снаряды, рывки, числа урона, лечение, смерть).
- Так тайминги логики (10 Гц) и анимаций (60 Гц) полностью развязаны: сменить
  темп боя или визуал можно, не трогая логику.

## Гекс-сетка

Зафиксированная система: **pointy-top, смещение odd-r** (`src/systems/Hex.ts`).
Используется **одинаково** в логике (HexGrid, Pathfinding) и в рендере (board.ts).

- Поле **11×7** гексов.
- Левые 3 колонки — зона игрока, правые 3 — зона врага, центр — рельеф.
- Рельеф центра генерируется детерминированно из `TERRAIN_SEED`.

### Модификаторы рельефа (к статам юнита на клетке)

| Рельеф | Скорость | Защита | Дальность (ranged) | Урон (ranged) |
|--------|----------|--------|--------------------|---------------|
| Равнина | ×1.0 | +0 | +0 | ×1.0 |
| Лес | ×0.6 | +3 | +0 | ×1.0 |
| Холм | ×0.9 | +1 | +1 | ×1.25 |
| Скала | непроходима (блокирует путь) | | | |

## Поведение юнитов (конечный автомат)

Состояния: `IDLE → ENGAGE → ATTACK → CHASE/REPOSITION → RETREAT → DEAD`.

- **Melee / Tank / Heavy** — сближаются (`ENGAGE`) и бьют в ближнем бою
  (`ATTACK`). Бьются до конца (не отступают).
- **Кавалерия** — то же, но помечается как `CHASE` (самая высокая `MOVE`).
- **Ranged** — держат дистанцию и стреляют (`ATTACK`); если враг подошёл вплотную
  — кайтят (`REPOSITION`, отходят), прижатые к стене бьют в упор. На холме
  получают бонус дальности и урона.
- **Support** — держится позади; если враг близко — отходит; иначе по кулдауну
  лечит ближайшего раненого союзника.
- **Отступление** (`RETREAT`): у `ranged`/`melee` при HP ≤ 30% — отход к своему
  краю (тяжёлые/танки/кавалерия отступать не должны по дизайну).

Движение — по **A*** (`src/systems/Pathfinding.ts`) с учётом занятых клеток,
стоимости рельефа и непроходимой скалы; отрисовка — плавный tween между центрами
гексов.

## Детерминизм

- `CONFIG.SEED` — seed боевого ГСЧ (криты/промахи), `CONFIG.TERRAIN_SEED` — seed
  рельефа. ГСЧ — mulberry32 (`src/systems/RNG.ts`).
- Порядок обработки юнитов фиксирован ⇒ расход ГСЧ детерминирован.
- **Одинаковый seed + одинаковое стартовое состояние ⇒ идентичный исход.**
  Проверено headless-тестом `npm`... см. ниже.

### Headless-проверка логики

`scripts/sim-test.ts` прогоняет бой без Phaser и проверяет, что он доходит до
результата и что два прогона с одинаковым seed идентичны:

```bash
./node_modules/.bin/esbuild scripts/sim-test.ts --bundle --platform=node --format=cjs --outfile=/tmp/sim.cjs && node /tmp/sim.cjs
```

## Этап 2 — мета-цикл кампании

Поверх боя надстроен **мета-слой** (`src/meta/`), полностью отделённый и от
боевой логики, и от Phaser. Сцены лишь читают/меняют `Campaign` и сохраняют его.

### Поток данных
`HubScene → CompositionScene → DeploymentScene → BattleScene → (исход) → HubScene`
Состояние живёт в `Campaign` (в реестре игры + LocalStorage). Между сценами
передаются только идентификаторы: `campaign.selectedIds` (выбор состава) и
`playerDeployment` (ростер-id + позиция).

### Экономика (`data/economy.ts` — тюнится в одном месте)
- Единая валюта, видна в хабе.
- Доход за волну: `incomeBase(wave) + victoryBonus(wave)` — только при победе.
- `HIRE_COST`, `HEAL_COST_PER_HP` (лечение пропорционально % потерянного HP),
  `ROSTER_LIMIT`, `COMPOSE_MIN/MAX` — всё в конфиге.

### Ростер и персистентность
- `RosterUnit` хранит полные статы, `currentHp` (между волнами) и
  `battleExperience`. В бой из него создаётся боевая `UnitModel` с
  `hp = currentHp` (раненые юниты воюют с пониженным HP).
- Сохранение в LocalStorage (`Campaign.save/load`): ростер, валюта, волна,
  nextId. При загрузке восстанавливается; нет/битый сейв → новая игра
  (стартовый ростер из 4 юнитов: танк, боец, стрелок, шаман).

### Исход волны (`BattleScene.showResult`)
- **Победа:** `campaign.applyVictory(report)` — начисление дохода, фиксация
  конца боя как `currentHp` (выжившие ранены, павшие → 0 HP, «сражён»), опыт,
  волна +1. Сохранение. → Хаб.
- **Поражение:** `campaign.applyDefeat()` — без потери валюты и юнитов,
  HP ростера не меняется (боевой урон не «прилипает»). → Выбор состава («Заново»).

### Генерация волн (`data/waves.ts` — заглушка до Этапа 4)
Состав врагов растёт **количественно и по статам линейно** с номером волны, на
тех же 9 юнитах эпохи 1. Детерминирована от `CONFIG.SEED + wave`.

### Тесты
- `scripts/campaign-test.ts` — мета-логика (35 проверок: newGame, save/load,
  найм, лечение, applyVictory/applyDefeat, волны).
- `scripts/integration-test.ts` — сквозной путь ростер → волна → бой →
  последствия (5 проверок, с детерминизмом).

```bash
./node_modules/.bin/esbuild scripts/campaign-test.ts --bundle --platform=node --format=cjs --outfile=/tmp/c.cjs && node /tmp/c.cjs
```

## Расширение на следующие этапы

Благодаря разделению слои можно менять независимо:

- Новая эпоха/юниты — добавить шаблон в `data/units.ts` (логика и UI подхватят
  автоматически через `ROLE_INFO`).
- Новый рельеф/модификатор — строка в `data/terrain.ts`.
- Новый тип поведения — состояние в `UnitController` (логика), при желании —
  отрисовка в `BattleScene` через новое `sim-event`.
- Сетевой бой/реплеи — `CombatSystem` уже детерминирован: достаточно
  синхронизировать seed + расстановку и крутить `update(dt)` на обеих сторонах.
