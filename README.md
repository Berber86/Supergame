# The Long Line

Веб-игра на **TypeScript + Vite + Phaser 3**: игрок ведёт индивидуально эволюционирующий ростер от Каменного века до далёкого будущего, расставляет 4–8 бойцов на гексах и наблюдает автоматический бой.

Реализованы этапы 1–4:

1. гекс-бой и конечные автоматы юнитов;
2. хаб, экономика, лечение, найм и сохранение;
3. опыт и индивидуальные ветки эволюции;
4. полный контент 8 эпох, специальные способности и адаптивные процедурные волны.

## Быстрый старт

```bash
npm install
npm run dev          # http://localhost:5173
npm run build        # typecheck + production bundle
npm test             # все headless-проверки
```

Требуется Node.js 18+.

## Игровой цикл

1. **Хаб** — ростер до 12 юнитов, лечение, найм форм эпохи I, эволюция готовых бойцов.
2. **Состав** — выбор 4–8 боеспособных юнитов.
3. **Расстановка** — drag-and-drop в левых трёх колонках или кнопка «Авто», учитывающая рельеф. В правой зоне уже показан детерминированный состав текущей волны.
4. **Бой** — автоматическая симуляция с фиксированным шагом 10 Гц.
5. **Победа** — доход, перенос HP и опыта, следующая волна. **Поражение** не фиксирует боевой урон, поэтому расстановку можно изменить и повторить.

Прогресс хранится в LocalStorage. Старые сейвы Этапа 3 мигрируют к новым рассчитанным статам и способностям с сохранением доли текущего HP.

## Восемь эпох и дерево эволюции

`src/data/evolution-tree.ts` содержит **72 юнита — по 9 на эпоху**:

| № | Эпоха |
|---:|---|
| I | Каменный век |
| II | Бронзовый век |
| III | Железный век |
| IV | Средневековье |
| V | Индустриальная эпоха |
| VI | Эпоха мировых войн |
| VII | Цифровая эпоха |
| VIII | Далёкое будущее |

В каждой эпохе представлены линии `Infantry`, `Ranged`, `Cavalry`, `Support`, `Siege` и общий баланс-каркас:

- `tank`;
- `melee-dps`;
- `ranged-dps`;
- `support-heal`;
- `support-buff`;
- `aoe-breaker`.

Каждый узел содержит имя, роль, HP/ATK/DEF/ATK_SPEED/RANGE/MOVE, флейвор, `is_branch_point`, рёбра следующей эпохи и, где предусмотрено, `special_ability`. Все пять линий имеют как минимум один полный путь I → VIII.

### Формула статов

Числа не подбираются вручную 72 раза. В `CONFIG.UNIT_STAT_SCALING` лежат коэффициенты роста эпохи:

```text
stat(epoch) = baseProfile × growth^(epoch - 1) × branchVariant
```

`baseProfile` задаёт силуэт роли, а ограниченные варианты (`assault`, `bulwark`, `marksman`, `skirmisher`, `lancer`, `raider`) создают выбор без произвольных скачков. Средние HP, ATK и DEF строго растут от эпохи к эпохе.

## Специальные способности

Ровно **24 из 72 юнитов (1/3)** используют один из восьми переиспользуемых эффектов:

| Тип | Эффект |
|---|---|
| `AreaHeal` | лечение нескольких союзников вокруг кастера |
| `Stun` | урон и временная остановка цели |
| `BonusVsTank` | усиленная атака только по tank/aoe-breaker |
| `Trap` | ловушка на свободном гексе, срабатывающая при входе врага |
| `Charge` | рывок по найденному пути и усиленный удар |
| `Suppress` | временное снижение скорости атак |
| `Shield` | временный запас поглощаемого урона |
| `SummonTurret` | временная неподвижная огневая точка |

Числа способности рассчитываются по эпохе через `ABILITY_POWER_PER_EPOCH`; один тип встречается у разных исторических форм с разной мощностью.

`SpecialAbilitySystem` не зашит в конкретные шаблоны. Он подключён к `UnitController`: FSM получает состояния `ABILITY` и `STUNNED`, а система предоставляет хуки атаки, движения, щита, ловушек и призыва. События `ability` передаются в Phaser так же, как обычные `move/attack/heal/death`.

## Процедурные волны

Основной API:

```ts
generateWave(worldEpochScore, waveNumber, terrainMap?)
```

Он возвращает 4–8 врагов с рассчитанным шаблоном и позицией.

- `worldEpochScore` — средняя эпоха всего ростера игрока, ограниченная диапазоном 1…8.
- Средняя эпоха врага остаётся внутри `worldEpochScore ± waveEpochSpread(wave)`.
- Разброс постепенно растёт, поэтому поздние волны смешивают соседние исторические формы и менее предсказуемы.
- В составе всегда есть настоящий танк; план резервирует melee/ranged и ограничивает повторы (не более 1 breaker, 2 support и 3 ranged), чтобы не возникали вырожденные стаки.
- Каждая пятая волна — **элитная**: +15% к HP/ATK/DEF всего отряда и дополнительная единица, пока не достигнут лимит 8.
- Номер волны даёт лишь небольшое ограниченное давление. Основная сложность адаптируется через прогресс эпох, а не бесконечное линейное раздувание врагов эпохи I.
- Базовый множитель врага 0,88 компенсирует игроку персистентные ранения и идеальную расстановку ИИ; элитный бонус применяется поверх него.
- Seed включает номер волны и `worldEpochScore`, поэтому одинаковое состояние кампании даёт одинаковое превью и бой.

### Тактическая расстановка врагов

В обеих deployment-зонах теперь встречаются безопасные леса и холмы, но нет блокирующих скал. Процедурный расстановщик сначала размещает ranged на свободных холмах, support — в тылу/лесу, tank и melee — ближе к фронту. Превью и бой используют одну карту через `terrainSeedForWave`.

## Боевая устойчивость

- AoE-breaker наносит 30% основного урона соседям цели, но уступает танку в живучести и стрелку в стабильном DPS.
- Support-heal лечит, support-buff временно ускоряет атаки союзника; без боевых союзников обе роли начинают атаковать сами.
- После 90 секунд включается overtime: юниты перестают бесконечно отступать/кайтить, урон растёт, лечение ослабевает. Это гарантирует завершение затяжных матчей.
- Рельеф влияет на поиск пути, скорость, защиту, дальность и урон стрелков.

Подробный чеклист и результаты первого прохода: [`docs/balance-v1.md`](docs/balance-v1.md).

## Архитектура

```text
src/
├── config.ts
├── data/
│   ├── evolution-tree.ts      # 72 узла + формула/профили/ветки
│   ├── special-abilities.ts   # типы и масштабирование 8 эффектов
│   ├── waves.ts               # адаптивный генератор + тактические позиции
│   ├── boardLayout.ts         # детерминированный рельеф волны
│   ├── terrain.ts
│   ├── units.ts               # UnitTemplate и индекс всех форм
│   └── economy.ts
├── entities/
│   ├── UnitModel.ts           # HP, FSM, кулдауны, статусы, щит
│   └── types.ts
├── meta/
│   ├── Campaign.ts            # ростер, worldEpochScore, экономика, save/load
│   ├── RosterUnit.ts
│   └── session.ts
├── systems/
│   ├── CombatSystem.ts
│   ├── UnitController.ts
│   ├── SpecialAbilitySystem.ts
│   ├── HexGrid.ts / Hex.ts / Pathfinding.ts / RNG.ts
│   └── sim-types.ts
├── scenes/
│   ├── HubScene.ts / CompositionScene.ts
│   └── DeploymentScene.ts / BattleScene.ts
└── ui/
```

Симуляция и мета-слой не импортируют Phaser. `CombatSystem` является единственным источником состояния, а сцена визуализирует очередь типизированных событий. Фиксированный порядок контроллеров и mulberry32 обеспечивают воспроизводимость.

## Тесты

```bash
npm run test:sim          # базовая боевая симуляция и детерминизм
npm run test:campaign     # экономика, save/load, XP, волны
npm run test:integration  # ростер → волна → бой → последствия → эволюция
npm run test:stage4       # 44 acceptance/balance-проверки Этапа 4
npm test                  # всё перечисленное + typecheck
```

`stage4-test` дополнительно прогоняет все 8 типов способностей, 40 процедурных волн и 40 контрольных боёв по линиям.
