# ARCHITECTURE — архитектура проекта

_Версия 1.0. Сессия 3, роль: 🧑‍💻 Coder._

## Стек

| Компонент | Выбор | Почему |
|---|---|---|
| Язык | TypeScript (strict) | Типы — самодокументация и защита от регрессий на десятки сессий |
| Сборка | Vite 5 | Быстрый dev-сервер, статический вывод в `dist/`, ноль конфигурации для Vercel |
| Тесты | Vitest 2 | Тот же экосистемный язык, что и Vite; юнит-тесты на логику (не рендер) |
| Рендер | Vanilla DOM (без фреймворка) | Игра простая; DOM достаточно; меньше зависимостей — дольше живёт проект |
| Платформа | Статический сайт | Жёсткое ограничение конституции: без бэкенда и БД, Vercel бесплатно |

Альтернативы (React/Vue, Phaser, Three.js) сознательно не взяты: для idle-кликера
с картой королевств и реликвиями они добавляют сложность без пользы. Если в будущем
понадобится Canvas/WebGL — это локальный модуль, не смена стека.

## Структура файлов

```
index.html               — точка входа (SPA)
vercel.json              — конфиг Vercel (framework: vite, output: dist)
vite.config.ts           — конфиг Vite + Vitest
tsconfig.json            — строгий TypeScript
.github/workflows/ci.yml — CI: тесты + сборка на push в main / PR

src/
  main.ts                — точка входа: инициализация, игровой тик, рендер-каркас
  style.css              — мультяшный стиль (временный, финальный арт — S8)
  core/
    types.ts             — все типы игры (GameState, контент-дефы) + ключ сейва
    events.ts            — шина событий (pub/sub) для связи модулей
    save.ts              — сейв/лоад localStorage, офлайн-расчёт с капом 8 ч
  economy/
    gold.ts              — клик и пассивный доход (чистые функции)
    pacing.ts            — контракт «≤ 1000»: потолок, целевая ставка, clamp
  content/
    servants.ts          — 3 слуги (MLP)
    buildings.ts         — 2 здания (MLP)
    kingdoms.ts          — 3 королевства (MLP)
    relics.ts            — 15 реликвий, 3 семейства + комбо-эффекты
  raid/
    raid.ts              — рейд-петля: вылет, этапы, урон/добыча, босс, победа/поражение
    synergies.ts         — синергии реликвий: комбо семейств (2+/4+) и именованные пары
    raid-ui.ts           — текстовые хелперы рейда (без DOM)
  ui/
    raid-panel.ts        — HTML-разметка панели рейда, синергий и коллекции
```

Правило из конституции: файлы кода ≤ ~200–300 строк. Если модуль растёт — дробить.

## Ключевые технические решения

1. **Состояние — единый объект `GameState`** (типы в `core/types.ts`). Вся игровая логика —
   чистые функции `(state, ...) → newState`; рендер подписан на шину событий (`core/events.ts`).
   Это даёт тестируемость и предсказуемость на десятки сессий.
2. **Сейв — localStorage, ключ `dragon-raids-save-v1`** (`core/save.ts`). Ключ инкрементируется
   при несовместимом изменении формата. Повреждённые данные → новый старт (без краша).
3. **Офлайн-доход** (GDD §3.5): при загрузке по `lastSavedAt` считаем `computeOfflineMs`,
   кап **8 часов** (константа `OFFLINE_CAP_MS`). Всё через чистую функцию — «подделку времени»
   покрывают юнит-тесты.
4. **Контракт «Малые числа»** (`economy/pacing.ts`): `GOLD_CAP = 1000`, `clampGold` защищает
   ресурсы, `TARGET_RATE ≈ 0.83 золота/сек` (потолок за ~20 минут), `isWithinPacing` — проверка
   баланса в тестах. Синергии/мета работают процентами, а не раздуванием цифр.
5. **Сила рейда связана с пещерой** (S6): урон = (8 + слуги + здания×2 + уровень дракона×2 + урон реликвий) × множитель синергий.
   Это митигация риска GDD §5.5 («idle обесценивает активную петлю»): idle-петля питает рейды, а не заменяет их.
   Синергии дают только проценты — контракт «≤ 1000» не нарушается (тесты в `raid/balance.test.ts`).
6. **Миграция сейвов без смены ключа** (`core/save.migrateState`): новые поля рейда (`offer`, `atBoss`)
   дописываются старым сейвам при загрузке — прогресс игрока не теряется.
7. **Данные контента отделены от логики** (`content/*.ts`): добавление реликвии/королевства —
   правка данных, не кода.
8. **CI**: GitHub Actions гоняет `npm test` + `npm run build` на push в main и на PR.
   Локально то же самое: `npm test`, `npm run build` — перед каждым коммитом.
9. **Vercel**: `vercel.json` с framework Vite; автодеплой из main (настройка в панели Vercel —
   шаг для человека, см. `CHECKLIST.md`).

## Планируемое развитие (по ROADMAP)

- S4: idle-петля полностью (найм слуг, покупка зданий, сейв/лоад UI).
- S5: рейд-петля v1 (карта, этапы, босс, выбор реликвий) — модуль `src/raid/`.
- S6 ✅: синергии реликвий (3 семейства, 9 синергий), рейд-петля в UI, баланс.
- S7: мета-прогресс (уровень, перерождение, достижения-стикеры).
- S8: контент/полировка (юмор, дневник, финальный арт).
- S9: MLP-интеграция и веха «MLP».

## Правила для будущих сессий

- Не ломать контракт «≤ 1000» (если нужно смягчить — выносить человеку).
- Не менять ключ сейва без необходимости; миграции — через версионирование ключа.
- Тесты на любую новую игровую логику; сборка и тесты — перед коммитом.
- Комментарии и строки — на русском; имена переменных/функций — английские.
